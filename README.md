# 娱乐档案 · Personal Entertainment Archive

一个**只在你自己电脑上运行**的个人娱乐记录工具。用海报墙或书架浏览看过的作品，给每部作品打分并留下修改痕迹，用时间轴记录每一次"开坑 / 补完 / 搁置"，需要时一键导出备份。

- 版本：以根目录 [VERSION](VERSION) 文件为准（网页副标题与设置面板显示当前运行版本，变更见 [CHANGELOG.md](CHANGELOG.md)）
- 技术栈：Python 标准库 + 原生 HTML/CSS/JS，**零第三方依赖**，不需要 `pip install`
- 数据：全部保存在本地 JSON 与本地封面文件，不上传任何服务器
- 独立音乐播放器提供全局播放、沉浸绑定、歌单沉浸三种模式；自动汇总音乐并按分类筛选，支持乱序和歌曲名、演唱者、绑定作品搜索。播放器收纳在角落图标弹窗中，搜索仅过滤结果，不会自动开始播放。
- 作品库统一承接分类筛选、系列集合与沉浸式作品详情；折叠/平铺墙面决定全屏浏览队列；首页作品也进入统一详情，编辑后返回原作品位置。

## 功能

作品库保留分类、状态、添加时间、搜索、排序和系列折叠/平铺筛选。点击作品进入连续滚动的沉浸详情；详情展示作品资料、来源字段、个人经历、自定义字段和评分记录，也可直接记录评分、添加/删除经历、添加自定义字段或删除作品。编辑后返回原作品位置。系列折叠时，全屏浏览按系列集合和独立作品排列；平铺时按单部作品排列。

**分类**：动漫 / 漫画 / 游戏 / 网文 / 出版书 / 影视剧 / 短剧。分类字段、状态文案都按分类自适应（动漫"追番中"、游戏"在玩"、短剧"在追"……）。

**创建作品时自动抓取信息**
- 动漫 / 漫画 / 游戏 / 影视剧：优先 Bangumi，其次豆瓣、AniList、Steam、Cinemeta、B站
- 出版书：优先豆瓣，其次 Bangumi、微信读书
- 网文：微信读书 → 搜索引擎定位官方页 → 粘贴链接解析（起点 / 番茄 / 刺猬猫）
- **Cinemeta 影视补充**：影视剧分类新增独立来源 Cinemeta（无需 API Key），同时查 `movie` 和 `series`，保留 IMDb ID（`tt` 开头），详情可带 IMDb / TMDB / TVDB ID；海报优先 `original`（实测 2000×3000），失败回退 `large`（780×1170）。它是英文资料源，不会覆盖 Bangumi / 豆瓣的中文标题与简介
- **微信读书高清封面**：搜索接口只给约 70px 宽的 `s_` 缩略图，程序会再从 `book-detail` 详情页取同名的 `t8_` 大图（实测约 347px 宽），校验宽度 ≥ 300px 后才采用；取不到就自动退回 `s_`，不影响资料导入
- **番茄书籍封面**：解析番茄详情页时，优先从页面 JSON-LD 的 `image` 字段取真正的书籍封面（`*-novel-sign`，实测有 p9 / p6 / p3 等变体），并排除 `author-img` / `p3-reading-sign` 作者头像；自动还原 HTML 实体 `&amp;` 和转义斜杠 `\u002F`。候选图片会用现有下载逻辑校验 HTTP 成功、文件大小和实际宽高，校验失败才回退；封面失败不会影响标题、作者、简介、字数等资料。
- **豆瓣电影高清海报**：搜索结果里的 `s_ratio_poster`（约 270px 宽）会换成 `l_ratio_poster`，实测《流浪地球》《你的名字。》《绝命毒师》均为 1080px 宽；下载后按图片文件头校验真实像素，失败或宽度不足就退回原海报。不解析豆瓣电影详情页
- **Bangumi 影视剧搜索**：影视剧分类会同时查 `type=6`（三次元）和 `type=2`（动画），按 Bangumi 条目 ID 合并去重后，在本地按标题相关度排序（标准化后完全一致 → 标题包含搜索词 → 搜索词包含标题 → 模糊匹配 → 其他），年份与封面完整度只作次级参考；任意一组查询失败时，另一组结果照常返回
- **编辑页站外搜索**：已入库的影视剧作品会显示爱奇艺 / 腾讯视频 / 优酷 / 哔哩哔哩，网文作品会显示起点中文网 / 番茄小说 / 刺猬猫。入口用当前作品标题生成搜索链接，在新标签页打开；找到正确作品后复制详情页 URL，回到编辑页下方「粘贴链接解析」继续。只做搜索跳转，不新增解析器、API 或依赖，其他分类不显示
- **统一资料书签**：`web/import-bookmarklet.js` 已接入影视和网文编辑页，一个书签按当前网站自动分流。TMDB 页面继续读取 JSON-LD，输出与旧 `tmdb-bookmarklet.js` 兼容的影视 JSON；优书网详情页读取 DOM，输出书名、作者、简介、标签、平台、状态、字数、评分、评分人数、原书链接和封面，`source.name=youshu`。影视页粘贴 TMDB JSON 继续进入现有预览/导入流程；影视页粘贴优书网 JSON 会提示到网文编辑页处理；网文页不会把优书网资料提交到 TMDB 接口。
- **优书网快捷搜索**：网文新建/编辑的「统一资料书签」区域提供「前往优书网搜索」，使用当前标题打开 `youshu.me/modules/article/search.php?searchtype=all&searchkey=...`，自动 URL 编码并在新标签页显示搜索结果；没有标题时提示先输入标题。TMDB 页面继续使用原来的「前往 TMDB 搜索」，两套入口互不影响。
- **优书网网文资料导入**：网文编辑页粘贴统一书签生成的优书网 JSON，先由 `/api/youshu/preview` 校验并显示书名、作者、简介、标签、阅读平台、连载状态、字数、优书评分、评分人数、原书链接和封面预览；确认后填入现有网文表单，仍需手动保存。新建作品会正常写入；编辑已有作品时，「只补空字段」保留已有非空标题、简介、标签、作者、来源、系列、别名和封面，「覆盖资料字段（含封面）」用优书网非空资料替换对应字段，并在优书网提供有效封面时替换已有封面；评分、阅读经历、我的字段和系列始终保留。已有作品原本无封面时，导入保存会直接使用优书网远程封面下载到本地（不会继承空 `cover` 字段）；只补空字段时已有封面不会被替换，覆盖模式下载失败也会保留旧封面，编辑表单会回退显示已有本地封面。优书网 ID 作为身份标识，新建时同 ID 已有条目会被阻止并提示打开已有作品编辑；同名但 ID 不同不会自动合并。缺失字段保持为空，不推断年份、原名或别名；占位图 `nocover.jpg`、非优书网图片域名和不安全封面地址不会下载或保存。封面白名单包含刺猬猫旧图床 `kuangxiangit.com` 与 `ciweimao.com`；GIF/WebP 动图会按实际格式保存。
- **TMDB 剪贴板导入**：影视剧新建第二步和编辑页「重新获取作品信息」提供「统一资料书签」区域。用户在 TMDB 详情页点击书签脚本，复制 JSON 后回到本项目粘贴；先预览标题、年份、类型、简介、标签、演职人员、集数和海报，确认后才保存。服务端校验 `source.name=tmdb`、`themoviedb.org` 的 `movie/tv` 数字 ID、标题和字段类型/长度；按 `movie|tv + 数字 ID` 识别作品，同 ID 更新已有作品，不按标题合并。已有作品导入时可显式选择「仅补空字段」或「覆盖 TMDB 字段」：前者保留已有非空资料，后者用 TMDB 的非空标题、原名、年份、标签、简介、演职人员、infobox 和封面替换，评分、经历、系列和用户字段始终保留；封面下载失败时保留旧封面。海报只接受 `image.tmdb.org` / `media.themoviedb.org`，优先 `original`（失败回退 `w500`），复用本地封面保存。不申请 TMDB API Key、不调用 TMDB API、不新增跨域接口、不要求安装浏览器扩展。项目保留旧 `web/tmdb-bookmarklet.js` 供已有「TMDB→项目」书签继续使用；导入区现在一键复制统一书签 `web/import-bookmarklet.js`；同一个区域还提供「前往 TMDB 搜索」，用当前标题打开 TMDB 搜索结果。
- 短剧：红果站内搜索（剧名 / 搜索结果页链接）
- 抓到的字段不是固定模板，而是**动态条目**：有几项就展示几项，缺的字段不会留一堆空白

**评分留痕**：10 分制、0.5 步进。每次改分记录时间、分值和原因（可选），可回看评分变化曲线。

**经历时间轴**：每条经历有日期、状态、内容。作品当前状态取自**经历日期最新的一条**（同一天多条按添加顺序），所以补充旧经历不会把状态改错。

**系列 / IP**：把跨媒介的作品聚合成一个系列（主系列 + 附加），系列可有独立评分、经历与封面；成员完全手动指定，墙上可折叠或平铺。

**浏览与筛选**：按分类、状态、添加时间筛选，按最近添加 / 最近经历 / 评分 / 标题排序，全文搜索标题、标签、简介、经历；主页每行显示数量支持小 / 中 / 大三档（中约为默认的 75%，大约为 50%），选择会记住。

**沉浸浏览**：单作品与系列都支持浮层 / 全屏展厅。系列卡片的「沉浸浏览」进入系列总览，展示完整跨媒介成员，可分类搜索并进入成员沉浸页后返回。编辑区粘贴图片直链并点击「添加」后，显示缩略图并把原图保存到本地，可拖动缩略图排序；已有远程背景可单独转为本地。完整 ZIP 备份包含已绑定的本地背景。背景汇总系列和成员手动添加的大图轮播，悬停成员可预览专属背景；无大图时用柔和背景和完整封面。全局支持顺序 / 随机、5–300 秒间隔；添加入口和操作见 [使用说明](使用说明.md)。

**两套主题 × 明暗**
- 展厅：海报墙，深色为默认；Apple 语义色，浅色为 `#fff` / `#f2f2f7`，深色为 `#000` / `#1c1c1e` / `#2c2c2e`
- 书架：一层层木质书架，作品是一本本立着的书（书脊按分类上色、右侧纸页边、纸质标签），顶栏与筛选区是刻在木板上的纹样
- 深浅两套配色，偏好保存在浏览器本地

**界面与设计**
- 视觉语言参考 [Lenso UI](https://github.com/LioRael/lenso-ui) 的 Apple-inspired Design、Liquid Glass、语义主题与原生交互，但**没有引入 React / StyleX / Base UI 或任何前端依赖**，而是把 Token、材质配方、组件构图和交互规律用原生 CSS/JS 适配到现有项目。
- 统一语义 Token：背景 / 表面、文字层级、填充、分隔、强调色、玻璃、圆角、阴影、字体与动效集中管理；主色为 system blue，评分为 system orange，状态使用蓝 / 绿 / 橙 / 红语义色。
- Liquid Glass 只用于浮动顶栏、详情浮层、Modal / 设置 / 系列弹窗、Toast 和海报上的评分 / 分类小控件；普通内容区、表单和详情信息块保持实色，避免整页玻璃。
- 详情是居中的玻璃 Sheet（最大 1240 × 900），不是旧的右侧抽屉；支持 Esc 逐层关闭、Tab 焦点陷阱与关闭后焦点回归，并适配 `prefers-reduced-motion` 和不支持背景模糊的浏览器。
- 圆角：内容 20px、字段 14px、小控件 10px、胶囊 999px；动效主曲线 `cubic-bezier(.32,.72,0,1)`，时长 160 / 240 / 340ms。

**备份与迁移**：导出 JSON（纯数据）或含封面 zip；导入支持 JSON / zip（zip 会自动把封面写回本地）；每次写操作自动快照，可回滚；设置里还有"清空数据"，清空前会自动整包备份到项目外。

## 快速开始

### 方式一：带便携运行时（推荐给"拷走就能用"的场景）

项目目录里放一份 `runtime\python\python.exe`（Windows 便携版 Python），双击 `启动.bat` 即可，无需安装 Python。

> 公开仓库里**没有** `runtime/`：它约 43 MB、几千个文件，超过 GitHub 网页上传的单文件 / 文件数限制。需要的话自己下载 Windows embeddable Python 解压到 `runtime\python\`，或直接用方式二。

### 方式二：用本机 Python

要求 Python 3.9+（推荐 3.10 以上）：

```bash
python server.py
```

然后打开 <http://127.0.0.1:8777>。换端口：

```bash
set GRDAG_PORT=8899   # Windows
python server.py
```

窗口就是服务本身，关掉窗口即停止；重复启动不会起第二个实例（会直接打开已有实例）。

## 数据与隐私

| 路径 | 内容 | 是否提交 |
|---|---|---|
| `data/library.json` | 作品、评分、经历 | 不提交（`.gitignore`） |
| `data/covers/`、`data/audio/` | 封面与本地 BGM | 不提交 |
| `data/image_cache/` | 搜索 / 详情预览图缓存 | 不提交 |
| `backups/`、`logs/` | 自动快照与运行日志 | 不提交 |
| `导入数据/*.csv` | 导入用的记录表 | 不提交 |
| `runtime/`、`*.zip` | 便携运行时与打包产物 | 不提交 |
| `design/` | 本地设计原型与截图（含大体积内嵌资源） | 不提交 |

- 服务只监听 `127.0.0.1`，局域网内其他设备访问不到。
- 抓取只访问公开页面 / 公开接口，不登录、不携带账号信息；封面只缓存到本地自用。
- 上传仓库前可在设置面板点「清空数据」，清空前会自动把整库和封面打包到项目目录之外。
- 公开仓库里的代码不写死本机路径、代理地址、账号或令牌；日志脱敏规则见「数据安全」。

| 短剧 | 红果 | 粘贴红果搜索结果页链接 |

影视剧还可使用「TMDB 剪贴板导入」：它不是自动搜索来源，也不调用 TMDB API，只读取用户从浏览器 TMDB 详情页复制的 JSON；适合补充中文标题、演职人员、集数和 IMDb ID。统一书签随项目提供，影视/网文编辑页均可一键复制；「前往 TMDB 搜索」会用当前标题打开 TMDB 搜索结果，不替代 Bangumi / 豆瓣 / Cinemeta / B站。

网文还可使用统一书签读取优书网详情页：它不登录、不调用 API，只解析用户主动打开的页面并复制 JSON；导入前先预览，确认后填入现有网文表单再保存。它不替代微信读书、官方页解析或手动填写。

## 已知限制

1. **Bangumi 需要代理**：程序会自动探测本机常见代理端口（7897 / 7890 / 10808 等），也可在设置里指定，或填 `direct` 强制直连。
2. 豆瓣影视详情页有反爬，只取搜索结果的标题 / 年份 / 海报（海报可升级到 `l_ratio_poster` 高清版），影视剧资料建议用 Bangumi。
3. 起点网页版有 WAF，程序走 `m.qidian.com` 移动页；番茄、刺猬猫可直接解析。
4. 搜索引擎桥接覆盖有限，低热度书可能定位不到，需粘贴链接或手动填写。
5. 红果分享短链 `/s/…` 里没有剧名，短剧请用剧名搜索或粘贴 `hongguoduanju.com/search/{剧名}`。
6. 单机单用户，无多端同步；想同步可把 `data/` 放进坚果云 / WebDAV。
7. **微信读书没有公开 API**：高清封面从 `book-detail` 页面解析 `t8_` 图，页面改版或请求失败时会自动退回 70px 左右的 `s_` 缩略图，资料导入不受影响。
8. **豆瓣电影搜索会短时限流**：连续快速搜索时 `subject_suggest` 可能返回空结果，隔一会儿再搜即可；图书搜索不受同一限制。
9. **TMDB / 优书网导入需要先安装统一书签脚本**：项目不申请官方 API Key，也不代抓 TMDB 详情页；影视/网文编辑页的导入区可一键复制 `web/import-bookmarklet.js`。用户需要在 Chrome / Edge 书签栏建一个名为「导入个人娱乐档案」的书签，把复制内容粘贴到网址栏；旧「TMDB→项目」书签仍可继续使用。TMDB 页面结构或 JSON-LD 变化时，需要同步调整脚本。优书网页面依赖用户已正常打开的登录态页面，脚本不读取 Cookie 或账号密码，不绕过 Cloudflare；页面 DOM 改版时需同步调整选择器。
10. **Cinemeta 只有英文资料**：标题、简介、演员名均为英文；它用于补搜索覆盖、IMDb/TMDB/TVDB ID 和高清海报，不替代 Bangumi / 豆瓣的中文资料。Cinemeta 是公开 addon，没有正式 SLA，接口或图片地址变化时可能失效。

更详细的操作说明见 [使用说明.md](使用说明.md)。

## 数据安全

- **主档案损坏不会被覆盖**：`data/library.json` 读不出来或结构不对时，程序停止一切写入并保留原文件，界面显示恢复页；可选用备份恢复，或确认后新建空档案（损坏文件另存为 `library.corrupt-时间.json`）。
- **恢复有校验、有回滚**：恢复前先看数量差异和「会丢几部作品」的警告，必须确认；随后自动保存恢复前安全快照，恢复后回读校验，失败自动回滚。
- **每天自动备份**：`backups/daily/` 每天一份，保留 15 天；写前快照和恢复前安全快照不在自动清理范围内。
- **撤销上一步**：顶栏撤销按钮或 Ctrl+Z，可连续撤销最近几步（作品信息、评分、状态、经历、系列关联）。
- **原子写入**：保存用临时文件 + fsync + 原子替换，断电不会写出半个档案。
- **日志**：`logs/app.log` 记录读写、备份、恢复与异常，密钥/令牌自动脱敏。

## 版本号

版本号遵循 `主版本.次版本.修订号`（语义化版本）格式，例如 `1.8.0`。它只在根目录 `VERSION` 文件里写一次（允许前导 `v`）。`server.py` 启动时读取它，网页副标题和设置面板显示的就是**本次运行加载的版本**；`/api/bootstrap` 还会返回磁盘上 `VERSION` 的当前值，两者不一致时设置面板会提示"项目目录里的 VERSION 已是 vX，重启程序后才会生效"。

版本递增按改动影响选择：

- **修订号（第三位）**：向后兼容的小修复、样式调整、文案或内部优化，例如 `1.7.23` → `1.7.24`。
- **次版本号（第二位）**：新增功能或较大的体验改进，同时保持现有数据和使用方式兼容；递增后修订号归零，例如 `1.7.23` → `1.8.0`。
- **主版本号（第一位）**：不兼容的重大改动，例如数据格式/核心操作方式需要迁移；递增后其余两位归零，例如 `1.8.0` → `2.0.0`。

数字位没有固定上限，也不需要等修订号累积到某个数才递增次版本。每个版本只选与本次改动级别相符的一位递增。发布时同步把 `web/index.html` 中静态资源查询参数的版本更新到同一个值，确保浏览器刷新缓存；其余版本显示仍从 `VERSION` 读取。

所以开发电脑改完版本、同步到使用电脑后，打开网页看一眼副标题或设置面板底部，就知道当前跑的是哪一版（没重启会明确提示）。发版时只改 `VERSION` 一个文件，不再改代码，也不再改 `README` / `CHANGELOG` 开头的版本声明。
